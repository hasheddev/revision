For sql queries to know where to optimize querywe use execution plan. It is raodmap generated by the database on how it will execute query step by step based on query and statistics
The plan is cached as it might be reused if a similar query is sent again

When a query is executed we have three options in our tool bar
Display estimated execution plan: predicts execution plan without query execution  
Include Actual execution plan: shows execution plan as it occurred after query is run
Include live query statistics: Shows real time execution flow as the query runs

If estimated does not match actual plan this indicates issues like inaccurate statistics or outdated indexes leading to poor performance

Clustered index scan = scans all data in an index to find matching row
For heap vs Index we can compare the plan for Orderby

Index seek > Clustered index scan > Table scan

Join algorithms
Nested loop: Compares tablew row by row, best for small tabels

You can save execution plan and compare them

We can get bad execution plans due to Outdated statistics or Toomany indexes

We can use Sql Hints: Commands added to a query to force the database to run it in a specific way for better performance

OPTION(HASH JOIN) after join condition(ON val = val) tells sql to use hash join
LEFT JOIN CONDITION WITH(FORCESEEK) load data with seek
WITH(INDEX(IndexName)) use index

Test all hints in all environments as performance may vary
